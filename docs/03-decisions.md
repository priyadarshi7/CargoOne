# Decision log (ADRs)

Status: Accepted unless noted. Newest decisions go at the bottom; supersede rather than edit.

| # | Decision | Why / trade-off |
|---|---|---|
| 1 | **Vite + React + TS as a PWA** (not Next.js) | App is offline-first and mostly behind login; SSR/SEO adds nothing. Cost: we host a separate API. |
| 2 | **FastAPI (Python)** backend | AI/vision stack is Python; one backend runtime instead of Node + Python. |
| 3 | **PostgreSQL 16** | Free hosting options (Neon/Supabase), JSONB for AI output, strong reporting SQL. |
| 4 | **SQLAlchemy 2.0 (async) + Alembic** (not Prisma, not raw SQL) | Prisma's Python client is community-maintained and needs Node; owner chose a full ORM + migrations. Cost: authorisation lives in API code (no RLS) — must be tested. |
| 5 | **AI Provider Abstraction Layer**, Gemini first | Provider/pricing may change; local model possible later. Interface `extract_pod()`, config-driven, fallback chain, cost/latency/accuracy logging. |
| 6 | Deterministic decision engine (AI extracts, rules decide) | Predictable routing: verified / needs review / retake; retake cap 2. |
| 7 | Hired drivers: signed SMS link, no login | Zero install; token scoped to one trip, expiring, revocable, rate-limited. |
| 8 | Compress on device to <300 KB | Dead zones + free-tier storage; DB constraint is the backstop. |
| 9 | Tally export as Tally Prime XML vouchers + CSV | Standard import path; no live Tally connection. |
| 10 | Voice: browser TTS now → recorded hi/mr audio before pilot | Recording needs a native speaker; TTS quality varies by phone. |
| 11 | Docker Compose for local dev | Reproducible Postgres; api/web containers added later. |
| 12 | Synthetic POD generator for dev/eval; fake test PII | No real PODs yet; collect 100–200 real ones in pilot week 1. Real data never in repo. |
| 13 | Git: protected `main`, short-lived branches, PRs, Conventional Commits, no AI co-author trailers | Owner's standard. |
| 14 | `md` (Managing Director) role: read-only executive dashboard | Deal signer; ROI proof from live data. |
| 15 | Mock AI provider reads ground-truth labels embedded in synthetic PNGs | Whole pipeline + decision rules testable offline, deterministic, free. Does NOT measure real accuracy. |
| 16 | Gemini model name is config (`GEMINI_MODEL`), key sent in header not URL | Model names change; keys must not leak into URLs/logs. |
| 17 | If all providers fail, caller queues POD for human review | Driver is never blocked by an AI outage. |
| 18 | `APP_ENV` guard: seed runs only in dev/test; non-dev startup rejects default/short `JWT_SECRET` | Demo credentials and the default signing key live in the repo; they must never work on a deployed server. |
| 19 | Server stores the uploaded bytes unmodified; validates by decoding (not by client MIME), 300 KB / 25 MP limits | Re-encoding on server would alter evidence; web client already compresses and strips EXIF. |
| 20 | Driver sees a trip as "not found" (404) if it is not theirs; POD upload idempotent on `client_upload_id` | No existence leak; offline retries are safe. |
| 21 | Native camera app via `<input capture>` instead of getUserMedia (for now) | Works on every cheap Android/WebView, handles focus/flash natively; in-app camera + framing guide is a later enhancement. |
| 22 | Offline queue id == server idempotency key; FIFO with strictly increasing stamps | Retries never double-submit or double-count a retake. |
| 23 | Tests run against a separate `<db>_test` database, created + migrated automatically | Test runs were leaving junk trips in the dev DB used for demos. |
| 24 | Reviewer corrections stored in `corrected_fields` beside untouched `ai_result`; approve requires LR to match the trip and a delivery date | Image/AI output stays auditable; a wrong-document POD cannot be approved by typo. |
| 25 | Gemini provider retries 429/5xx twice (0.7 s, 1.8 s) then fails over; errors carry the HTTP status only | Live testing hit transient 503/429s on the free tier; response bodies can echo document text (PII). |
| 26 | Tests force `AI_PROVIDER=mock` and an empty key regardless of `.env` | Real keys must never make tests slow, flaky, or send images to a third party. |
| 27 | Settings read repo-root `.env` and `api/.env` (latter wins) | Developers put the file in either place. |
| 28 | Creating an invoice makes a draft inside CargoOne only; exporting stamps `exported_at`; nothing is sent to clients | Brief: invoices are never sent automatically. |
| 29 | One invoice = one client, one voucher in Tally (party Dr / Freight Income Cr); numbers from a Postgres sequence `CO/<FY>/<n>` | Matches how transporters bill; sequence is race-free for concurrent billers. Gaps are possible and acceptable. |
| 30 | PDF uses "Rs." not the rupee sign | The built-in PDF font has no rupee glyph; embed a TTF font later for the symbol and Devanagari. |
| 31 | CSV export neutralises cells starting with = + - @ | Prevents spreadsheet formula injection. |
| 32 | KPI definitions: 24 h share = first POD upload <= 24 h after delivery (over trips delivered > 24 h ago); POD-to-invoice = verified -> invoiced; lost/disputed = rejected; working capital = the brief formula on annualised window freight | Makes every dashboard number reproducible and testable; `first_pod_at` is stored because retakes overwrite `pod_uploaded_at`. |
| 33 | Dashboard defaults to the last 30 days (90 selectable) | A 90-day window blends before/after eras and understates current performance. |
| 34 | Demo data generator is dev-only, deterministic, DEMO- coded, creates no verified-unbilled trips, and the dashboard shows a banner while any are in the window | Dashboards need history to demo, but fabricated numbers must never pass as real. |
| 35 | Charts: ordinal blue ramp for age buckets (not red/green), single-series lines with a dashed target, hover readout, table view under every chart, status shown with icon + label | Colour never carries meaning alone; follows the dataviz guidance. |
| 36 | E2E runs on its own stack (API :8001, web :5174, `cargoone_e2e` DB dropped/recreated each run, refuses non-`_e2e` names) with a scripted mock AI (`MOCK_SCENARIO`) | Browser re-encoding strips the label the mock reads, so the mock needs a scripted mode; isolation keeps dev data safe. |
| 37 | Screenshots are saved by E2E (git-ignored) and reviewed by eye after UI changes | Visual bugs (stale badge, ambiguous offline icon, misleading 0% KPI) passed every assertion and were only visible in pictures. |
| 38 | Upload links store only a SHA-256 of the token; 72 h TTL; one active link per trip | A DB leak must not leak working links; limits exposure of a forwarded SMS. |
| 39 | Guess-throttling applies only to UNKNOWN tokens (a blocked IP can still use a valid link) | Carrier NAT puts many real drivers behind one IP; found by a test - the first version would have locked them out. |
| 40 | Upload rules live in one service (`app/pod/ingest.py`) used by the logged-in and the link route; one shared `CaptureFlow` component on the web | Two entry points must never drift apart on retake cap, size limits, idempotency or AI routing. |
| 41 | Mock SMS only (in-memory outbox, masked phone in logs/audit) | Real provider needs DLT-registered templates; the interface is ready. |
| 42 | Import is two-step (dry-run report, then commit) and idempotent by Trip ID; trips with POD activity are never modified; blank cells never erase data | Real daily files are messy and re-sent; the LR number on a trip with a POD is evidence. |
| 43 | Import accepts the client's own sheet layout ("Company B (cement)", "MH17 BY 3092 (hired)", ignored POD Status/Remarks) | Lowest friction for Company A; their sheet lacks LR/e-way bill columns, so the daily file must add them (reported as a clear error). |
| 44 | Client view link is a separate, narrower link kind (`client_view`): one trip, verified/billed PODs only, no amounts or consignee PII, 30-day expiry, every open audited by a non-secret handle | A client needs proof, not our commercial data; the link dies if the POD stops being verified. |
| 45 | MD digest is a PDF built from the dashboard's own computed numbers (same function, no second calculation); downloaded on demand, email later | The PDF can never disagree with the screen; email needs a provider decision. |
| 46 | Own tiny i18n layer (typed keys, English fallback, localStorage choice) instead of a library | ~3 languages, no plurals/ICU needs yet; keeps the bundle small. Revisit if more languages are added. |
| 47 | Account lockout stored in the database (5 failures, 15 min) plus identical in-memory throttles for unknown identifiers and per address; sessions revoked by a per-user token version | Lock survives restarts and multiple processes; unknown accounts cannot be told apart from real ones; a timestamp check had a same-second hole, a counter has none. |
| 48 | PIN reset = office issues a random 6-digit temporary PIN shown once; account flagged `must_change_secret`, enforced in the API (only /auth/me and /auth/change-secret work) | The office knows the temporary PIN, so it must not survive; server-side enforcement means a modified client cannot skip it. Read out by phone for now; SMS delivery waits on the SMS provider. |
| 49 | Dark mode via CSS variables on `data-theme` with its own colour steps (not an inversion); solid buttons use a `on-solid` token (dark text in dark mode) because no single accent passes contrast with both white text and the dark surface | Contrast verified by eye on all office screens; theme applied by an inline script before paint to avoid a white flash. |
| 50 | Translations live in one file per language (`lib/i18n/{en,hi,mr}.ts`); English defines the keys; a unit test fails if hi/mr have unknown keys, missing keys or different placeholders | Keeps the three languages in step as screens are added. Server error messages stay English for now. |
| 51 | Trips have a lifecycle state separate from POD status; a trip occupies its vehicle/driver from its start until its planned end (default one day); clashes are 409 with the clashing trip codes and can be overridden explicitly; only ops can plan (billing views) | Planning must warn, not forbid (a real operation has exceptions), and the override must be deliberate and audited. POD capture is not gated on state, so existing flows are unaffected. |
| 52 | Live GPS from the driver's browser (PWA), consent stored server-side and enforced on every ping, fixes only while a trip is `in_transit`, visible to ops/MD only, client link rounds to ~100 m and hides the driver, 30-day retention | DPDP: location is personal data and needs a purpose, consent and limited retention. A PWA cannot track in the background; the limit is stated to users and in the roadmap. |
| 53 | Map = Leaflet + OpenStreetMap tiles (free), lazy-loaded; dark mode inverts tiles with CSS | No API key or cost for the pilot. The public OSM tile server is for light use only; move to a hosted tile provider before heavy use. |
| 54 | Expenses count in trip profit only once approved; pending are shown beside; a reject needs a reason the driver sees | Profit must not be silently understated or overstated; drivers learn why. The margin card warns when many trips have no costs recorded yet. |
| 55 | Fuel mileage anomalies use the truck's own median (needs 3 good legs) and plain physical limits; the median ignores flagged legs | A bad fill cannot hide by dragging the average down; no fixed national norm is imposed on trucks of different size and load. |
| 56 | Master data is never deleted, only made inactive (`is_active` on users, vehicles, clients, vendors); deactivating signs a person out at once and is refused while they or the truck are on a live trip | Old trips, invoices and the audit trail must keep pointing at real records; a leaver must lose access immediately |
| 57 | Roles for setup: ops head (and admin) change drivers/trucks/clients/vendors, billing may read them, only the admin manages office staff (cannot mint admins or lock themselves out); a hired driver/truck is just a link to a vendor | Smallest rule that matches who does the work; staff accounts are the most sensitive thing to hand out; one `vendor_id` covers hired drivers and trucks without a second model |
| 58 | PWA via vite-plugin-pwa: service worker precaches only the built app shell, never API calls; auto-updates; disabled in `pnpm dev`; a failed `/auth/me` keeps the cached profile only when there was no network, an answer from the server (401) still signs out | Drivers open the app in dead zones and must still capture PODs; data must never be served stale; dev must never show old pages. Installing and GPS both require HTTPS |
| 59 | On-phone photo check is plain pixel statistics on a 640 px greyscale copy (Laplacian variance for blur, mean brightness, share of blown-out pixels with little surviving print, flat frame), thresholds tuned on synthetic PODs (sharp ~2700-3100, 2 px blur 89, 3 px blur 17), advisory only: the driver can always send anyway | Instant feedback before the truck leaves the gate without shipping a model to low-end phones; a false alarm must never block a delivery. Real-photo accuracy must be re-measured in the pilot and the limits adjusted (`LIMITS` in `quality.ts`) |
| 60 | One "Needs attention" endpoint feeds every role; reminders are a manual button (not a background job yet), at most one SMS per trip per 24 h enforced from the audit log, and the response says when the sender is the simulated one | Ops decides when to chase; no spam if pressed twice; an honest UI while SMS is mocked. A scheduler is a small add-on once a real provider exists |
| 61 | The POD reader is judged by unsafe errors first (a bad POD that would be verified must be zero), then friction, then field accuracy; the harness runs the real decision rules on the model output and can fail a build | One wrongly verified POD is a billing mistake; a needless retake is only a minute. Headline accuracy alone would hide that asymmetry |
| 62 | Truck and driver papers are stored as files in the same private storage (table `documents`, one current file per owner and kind, type decided from the file's first bytes, 3 MB cap, images re-validated by decoding, replacing deletes the old file); truck papers are readable by ops and billing, a driver's licence only by ops/admin | A licence photo is personal data (DPDP): least access, no public URL, nothing kept that is no longer current |
| 63 | A truck that is not `available` or has any expired paper, and a driver with an expired licence, cannot be planned onto a trip (422 with the reason); there is no override | Running an uninsured or unfit truck is a legal and financial risk, not a scheduling preference like a clash |
